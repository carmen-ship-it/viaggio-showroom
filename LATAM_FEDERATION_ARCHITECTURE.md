## Core Principle

**Transfer topology. Never transfer weights without evidence.**

A node in Peru does not inherit Santa Cruz edge weights because both sell SUVs. It inherits **which objections exist**, **how they compound**, **which proof classes resolve them**, and **which DNA clusters predict path behavior** — then **re-learns every weight** from local outcomes until minimum-N thresholds are met.

Federation is how CPI-OS escapes the single-dealer ceiling without cloning a pilot that was trained on Bolivian high-trust decision physics.

# 1. Purpose

This specification defines how **CPI-OS** (Considered Purchase Intelligence Operating System) expands intelligence from **Santa Cruz** (node zero) to **Bolivia** and eventually **Latin America** — without diluting the moat, poisoning learning with false transfer, or treating geography as a translation problem.

### What federation solves

| Problem | Without federation | With federation |
|---------|-------------------|-----------------|
| Second city launch | Rebuild graph from zero | Inherit CPO + topology; learn local weights |
| Cross-market learning | Siloed pilots | Anonymized benchmark layer after N nodes |
| Category expansion | Automotive-only trap | Layer 3 vertical abstraction on same kernel |
| Competitive imitation | Copy kiosk UX | Cannot copy 3-year multi-node outcome corpus |
| Executive decisions | Santa Cruz anecdotes | Regional lift packets with lineage |

### What federation is not

- Not multi-tenant SaaS architecture  
- Not CRM data sync between dealerships  
- Not translating US automotive playbooks into Spanish  
- Not merging graphs because nodes share an OEM brand  
- Not licensing raw weights to partners without governance  

### Federation unit of value

The federated asset is **validated intelligence structure** — Decision Graph topology, DNA cluster definitions, Marketing DNA genotype maps, CPO versions, and holdout-promoted proof efficacy — **scoped by layer** and **stamped with evidence lineage**.

# 2. Federation Principles

| ID | Principle | Operational meaning |
|----|-----------|---------------------|
| **FP-01** | **Node zero is source, not template** | Santa Cruz (SCDG) defines ontology candidates and topology hypotheses; never authoritative weights outside Layer 0 |
| **FP-02** | **Topology before weights** | New nodes receive edge *types*, compound objection *patterns*, and proof *classes* — not lift coefficients |
| **FP-03** | **Evidence gates promotion** | No weight, DNA affinity, or Marketing DNA curve crosses a layer boundary without holdout-validated minimum-N |
| **FP-04** | **Layer isolation by default** | Layers do not merge; they compose. Merged views are read-only aggregates for executives and benchmarks |
| **FP-05** | **Outcome truth > volume** | A 500-edge Santa Cruz path corpus outranks a 5,000-edge unlabeled import |
| **FP-06** | **Household is the cross-border unit** | Customer DNA federates at household decision-unit genotype — not individual CRM contact |
| **FP-07** | **Local shock nodes are first-class** | Every new node may add nodes (e.g., `altitude_financing`, `port_import_trust`) without forking CPO |
| **FP-08** | **Marketing DNA does not travel as creative** | Transfer message *archetypes* and genotype *selection effects* — not ad copy or channel mix weights |
| **FP-09** | **Salesperson DNA stays node-local** | Skill signatures are institutional; match matrices do not export by default |
| **FP-10** | **Ontology governance is federated** | CPO changes require layer steward approval + backward compatibility window |
| **FP-11** | **Benchmarks are earned, not assumed** | Network intelligence products activate only after anonymization contract + ≥10 nodes (see §9) |
| **FP-12** | **Lineage is moat metadata** | Every transferred edge carries `source_layer`, `evidence_count`, `holdout_status`, `valid_until` |

### Federation decision hierarchy

```
Local outcome evidence (node)
    → Layer steward validation (country / vertical)
        → CPO governance board (cross-layer)
            → Executive Copilot promotion packet (human approve)
                → Benchmark anonymization tier (optional export)
```

# 4. Node Architecture

A **node** is the smallest federation unit that owns an outcome-labeled learning loop.

## 4.1 Node definition

```yaml
cpiNode:
  nodeId: uuid
  nodeName: string                  # e.g. viaggio_santa_cruz
  layer: 0 | 1 | 2 | 3
  vertical: automotive | real_estate | insurance | ...
  geography:
    country: ISO-3166
    city: string
    altitude_band: lowland | highland | coastal | ...
  status: pilot | learning | validated | licensed | benchmark_eligible

  intelligenceEstate:
    decisionGraph:
      graphId: string
      edgeCount_labeled: int
      topologySource: nodeId | layer_template
      weightAuthority: local_only
    customerDNA:
      profiles: int
      clusters: int
      layerTag: int
    salespersonDNA:
      profiles: int
      exportable: false             # default
    marketingDNA:
      campaigns: int
      archetypes: int
    cpoVersion: semver

  governance:
    steward: role                   # floor + executive
    outcomeDiscipline: float        # % sessions with lost_reason
    holdoutCadence: weekly
    minimumN_policy: tier

  federation:
    upstreamLayers: [layer_id]
    downstreamConsumers: [nodeId]   # licensed children
    benchmarkParticipation: opt_in | anonymized | none
    lineageRoot: nodeId             # always trace to node zero
```

## 4.2 Node lifecycle

```
Proposed → Topology seeded (weights uninformative)
    → Learning (outcomes accumulate, holdouts run)
        → Validated (minimum-N met per critical edge class)
            → Federation parent (may seed child nodes)
                → Benchmark eligible (anonymization contract signed)
```

## 4.3 Node types

| Type | Description | Example |
|------|-------------|---------|
| **Anchor** | Source node; full authority | Santa Cruz (L0) |
| **Sibling** | Same layer, same country | La Paz, Cochabamba |
| **Regional** | L2 licensed automotive | Lima partner |
| **Vertical** | L3 non-automotive | Real estate pilot |
| **Observer** | Benchmark-only contributor | Anonymized multi-brand node |

## 4.4 What crosses node boundaries

| Asset | Default | Condition for export |
|-------|---------|----------------------|
| CPO version | Yes (read) | Governance board approval |
| Graph topology | Yes | Parent validated |
| Graph weights | **No** | Never without local re-learning |
| Customer DNA profiles | **No** | Never raw; cluster stats only in benchmark tier |
| Salesperson DNA | **No** | Node-local |
| Marketing DNA curves | Partial | Archetype only until local N |
| Override corpus | **No** | Anonymized patterns in benchmark tier |
| Assisted margin ledger | Aggregated | Benchmark tier only |

# 5. Graph Transfer Rules

Full graph spec: [DECISION_GRAPH_SPEC.md](./DECISION_GRAPH_SPEC.md)

## 5.1 Transferable (topology)

| Element | Transfer form |
|---------|---------------|
| Node types | `fear`, `proof`, `action`, `outcome`, `compare`, `permission` |
| Edge types | `resolves`, `triggers`, `precedes`, `compounds_with` |
| Compound objection grammar | `china_brand AND spouse`, `payment AND defensive` |
| Entry subgraph templates | Meta-sourced vs walk-in (channel-conditioned) |
| Proof classes | `service_network`, `resale_data`, `safety_cert` — not specific copy |
| Holdout catalog | Which edges require re-validation in target node |

## 5.2 Non-transferable (weights)

| Element | Why |
|---------|-----|
| Edge lift coefficients | Local market confound |
| Path length priors | Channel mix differs |
| Proof efficacy rankings | Creative and competitive context |
| Cyclic compare revisit rates | Inventory and OEM differ |
| Margin-optimal path selection | Finance and tax differ |

## 5.3 Seeding protocol (L0 → child node)

```
1. Clone topology → child graph (all weights = prior 0.5, evidence_count = 0)
2. Inject local shock nodes (steward proposal → CPO board)
3. Map proof classes to local assets (intelligence mapping, not content clone)
4. Run parallel holdouts on top-10 critical edges from parent
5. Freeze any edge where child holdout contradicts parent lift (|Δ| > threshold)
6. Begin local learning loop; parent weights never auto-merge
```

## 5.4 Merge rules (forbidden vs allowed)

| Operation | Verdict |
|-----------|---------|
| Merge Santa Cruz + La Paz weights at N < 500 each | **Forbidden** |
| Aggregate anonymized path *statistics* for benchmark | **Allowed** (tier 2+) |
| Promote La Paz edge to L1 canonical | **Allowed** after holdout + steward sign-off |
| Child inherits parent weight on launch day | **Forbidden** |
| Executive Copilot shows blended "LATAM" path recommendation | **Forbidden** until L2 validated |

## 5.5 Graph integrity across federation

| Rule ID | Rule |
|---------|------|
| **GT-01** | No outcome node without `lost_reason` if lost — any node |
| **GT-02** | MkIE shock active → freeze cross-layer promotion |
| **GT-03** | Override edges never deleted — federated learning signal |
| **GT-04** | `evidence_count < N` → weight frozen |
| **GT-05** | Cross-layer edge must carry `lineage[]` |
| **GT-06** | Public compare facts ≠ proprietary edges (moat is paths) |

# 6. DNA Transfer Rules

Full spec: [CUSTOMER_DNA_ENGINE.md](./CUSTOMER_DNA_ENGINE.md)

## 6.1 What Customer DNA is in federation

Customer DNA federates as **genotype schema + cluster definitions** — not individual profiles.

| Transferable | Non-transferable |
|--------------|------------------|
| Genotype slot enums (`primary_concern`, `co_decision_mode`, `buying_style`) | Individual `dnaId` records |
| Cluster labels ("Trust-Anxious Co-Decision") | `graphAffinity.optimal_path_template` weights |
| Slot priors (uninformative 0.5) | `proofs_high_lift` lists from parent node |
| Phenotype taxonomy | Household identifiers |
| Cross-node cluster *existence* hypothesis | Cross-node cluster *prevalence* without local N |

## 6.2 Cluster transfer protocol

```
1. Parent publishes cluster definition:
      genotype ranges + phenotype markers + minimum separation tests
2. Child node assigns incoming households to clusters locally
3. Child validates: P(won | cluster, local path) independent of parent
4. Cluster merge across nodes requires:
      - Same CPO version
      - Local sample ≥ N_c per cluster (recommended N_c = 150)
      - No significant genotype drift vs parent (or relabel)
5. New local cluster → propose CPO extension (not silent fork)
```

## 6.3 graphAffinity localization

`graphAffinity` is **always node-local**. A La Paz Trust-Anxious household gets La Paz path templates — seeded from topology, not Santa Cruz weights.

## 6.4 Salesperson DNA federation

Salesperson DNA is **node-local by default** (organizational asset).

| Rule | Rationale |
|------|-----------|
| No export of individual consultant profiles | Privacy + incentive gaming |
| Skill *archetypes* (trust_closer, permission_facilitator) may inform L3 vertical packs | Abstract skill grammar |
| Match matrix (Customer DNA × Salesperson DNA) never crosses nodes | Lead quality and staff differ |
| AI-assist mode signatures may aggregate into benchmark tier | Anonymized capability gaps |

## 6.5 DNA decay across layers

| Event | Federation behavior |
|-------|---------------------|
| Customer relocates cross-city | New node assignment; genotype persists, graphAffinity resets |
| 90-day inactive | Confidence ↓ locally; no cross-node profile sync |
| Market shock (MkIE) | Phenotype overlay per node; no federated erase |
| Cluster stereotype alert (I-02) | Steward review; may split cluster in one node only |

# 7. Marketing DNA Transfer Rules

Marketing DNA is the **acquisition-side genotype** — which messages and channels *select for* which Customer DNA clusters before graph entry.

Reference: [LEVEL11_INTELLIGENCE_ARCHITECTURE.md](./LEVEL11_INTELLIGENCE_ARCHITECTURE.md) §4

## 7.1 Transferable

| Element | Form |
|---------|------|
| Channel archetypes | `meta_mobile`, `radio_qr`, `whatsapp_inbound`, `referral` |
| Message archetypes | `trust_proof_hero`, `compare_anchor`, `payment_reassurance` |
| Genotype selection hypothesis | "Meta creative X tends to select Compare-First" — as **hypothesis**, not weight |
| Entry path template | First 3 edge *types* after touch |
| Drift metrics definitions | `genotypeDrift`, `inMarketMismatch` formulas |
| Holdout creative experiment structure | What to re-test locally |

## 7.2 Non-transferable

| Element | Why |
|---------|-----|
| `acquiredGenotypeMix` percentages | Audience and algorithm differ |
| `assistedGP_per_dollar` | CAC and margin structure differ |
| Creative copy and assets | Cultural and regulatory context |
| Channel spend allocation | Market-specific |
| `typicalEntryPath` edge IDs with weights | Local graph entry differs |

## 7.3 Marketing DNA seeding protocol

```
1. Child inherits archetype catalog from parent layer
2. All responseSignature metrics start at zero
3. First 90 days: parallel run of parent-holdout creative *archetypes* (not copies)
4. genotypeDrift vs campaign brief → steward alert (not auto-optimize)
5. Marketing × Customer DNA loop closes locally before any cross-node merge
```

## 7.4 Cross-node marketing intelligence (allowed aggregate)

After benchmark tier activation:

- Anonymized rank of channel archetypes by **genotype selection efficiency** (not creative)  
- Regional drift alerts: "Trust-Anxious acquisition rising in Andean nodes"  
- No campaign-level identifiable data

# 8. Ontology Governance Across Regions

**Considered Purchase Ontology (CPO)** is the federated contract — the shared vocabulary without shared weights.

## 8.1 Governance structure

```
CPO Governance Board
├── Layer 0 Steward (Santa Cruz floor + executive)
├── Layer 1 National Steward (Bolivia)
├── Layer 2 Regional Steward (LATAM automotive — per country)
├── Layer 3 Vertical Steward (considered purchase kernel)
└── Federation Architect (lineage + compatibility)
```

## 8.2 Change classes

| Class | Example | Approval |
|-------|---------|----------|
| **Instance** | New proof node `viaggio_service` | L0 steward |
| **Extension** | New `altitude_performance` concern | L1 steward + board notice |
| **Kernel** | New genotype slot | Board majority + 90-day compatibility window |
| **Deprecation** | Retire obsolete objection type | Board + migration map for all nodes |

## 8.3 Versioning rules

```yaml
cpoVersion:
  major: breaking slot or enum change
  minor: new optional node type
  patch: definition clarity, no graph migration

compatibility:
  childNode may lag parent by: 1 minor version
  cross-layer queries require: same major version
  benchmark tier: reports on major version family only
```

## 8.4 Ontology drift failure mode

| Symptom | Detection | Response |
|---------|-----------|----------|
| Lima uses `spouse` where Bogotá uses `family_influencer` for same behavior | Cross-node cluster mismatch | CPO harmonization sprint |
| Silent local fork | Lineage audit | Freeze promotion; merge or formalize |
| US-import taxonomy | Steward review | Reject; L0 Santa Cruz is source |

## 8.5 Palantir-class critique response

> "No ontology governance / federation"

CPO board + layer stewards + versioned lineage + per-node holdout gates = **governed federation**, not a data lake with flags.

## 9.2 Benchmark products (intelligence outputs)

| Product | Contents | Consumer |
|---------|----------|----------|
| **Path lift index** | Anonymized proof class efficacy by DNA cluster | Licensed nodes, executives |
| **Genotype shift radar** | Regional drift in acquisition vs in-market DNA | Marketing stewards |

## 9.3 Anonymization tiers

| Tier | Data | Use |
|------|------|-----|

# 10. Privacy Requirements

Federation amplifies privacy risk — more nodes, more temptation to merge profiles.

## 10.1 Principles

| ID | Requirement |
|----|-------------|
| **PR-01** | Household graph requires consent flag per edge (spouse, family) |
| **PR-02** | Customer DNA cluster labels never customer-facing |
| **PR-03** | No DNA use for pricing, credit, or insurance underwriting |
| **PR-04** | Data minimization: genotype slots only — no inferred income |
| **PR-05** | Cross-border transfer = aggregates by default; raw profiles forbidden |
| **PR-06** | Right to erasure applies per node; federation lineage anonymized after erasure |
| **PR-07** | Licensed partners own local consent regime; Viaggio owns methodology audit |
| **PR-08** | AI disclosure rules respected per country automotive advertising law |
| **PR-09** | Benchmark tier re-identification test before each release |
| **PR-10** | Salesperson DNA not exportable — coaching only, not surveillance |

## 10.2 Regulatory posture (LATAM)

Profiling regulation evolves (E-01). Federation architecture assumes:

- **Bolivia pilot** establishes consent ritual and household merge policy  
- **Each L2 node** adds local legal review before benchmark participation  
- **Layer 3 verticals** may trigger stricter regimes (insurance, credit-adjacent)  

## 10.3 Privacy failure → federation freeze

Any unresolved E-02 (household without consent) or E-03 (DNA → pricing) at any node → **freeze cross-layer promotion** for that node until remediated.

# 12. Failure Modes

|----|---------|--------------|------------|
| **F-01** | Weight clone on launch | Child paths match parent lifts before N | Enforce prior 0.5 seeding |
| **F-02** | Topology without outcomes | High edge count, zero `lost_reason` | Freeze child promotion |
| **F-03** | Cross-border stereotype | Cluster lift fails holdout in 2+ nodes | Split cluster; local relabel |
| **F-04** | Marketing archetype overfit | genotypeDrift low but win rate collapsing | Creative re-test; not weight import |
| **F-05** | CPO fork | Same word, different graph semantics | Lineage audit; harmonization |

| **F-09** | MkIE shock promotion | Corolla promo week promotes false proof | MkIE freeze (GT-02) |

| ID | Failure | Mitigation |
|----|---------|------------|
| **O-F01** | Child node incentivized on units, not labels | Align floor comp with outcome discipline |
| **O-F02** | Steward vacancy | Default freeze on cross-layer promotion |

## 12.3 Recovery protocol

```
Detect → Freeze promotion at affected layer
    → Root cause (lineage audit)
        → Remediate locally
            → Re-run holdouts
                → Steward sign-off → resume federation
```
